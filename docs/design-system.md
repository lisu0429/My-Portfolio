## 1. 视觉基调：烟雾 / 雾气

**场景**：夜间 Hero、沉浸式叙事。信息始终可读，氛围靠雾与光承载。

### 色彩

- 底色：深蓝夜雾 `#070A0E`，页面上下各叠一层柔光径向渐变
- 雾青（主）`#A9DEE8` —— 标签、数字、描边高亮
- 暖光（辅）`#E8BE96` —— 主 CTA、暖侧雾带，形成舞台灯的冷暖对比
- 前景文字：`#EDF3F7` / `#9FB1BD` / `#66767F`，全部带深色 text-shadow，压在前面的雾上仍然可读
- 首屏名字用 `<TechText />`（canvas）渲染：Manrope 800，填充 `#EFF6F9`，强调色雾青；指针附近字母溶解为虚线矢量轮廓，选框带尺寸标注，可拖拽 / 点击弹起，鼠标离开时以 0.6 倍速自动扫过
- 名字上方散布三个小标签（PORTFOLIO / [AI PRODUCT MANAGER] / [2026]），导航链接居中

色值全部收在 `src/styles/tokens.css`，组件里不写死颜色。

### 雾的三种做法

1. **雾带**：大尺寸（50–95vw）径向渐变体 + `blur(34–58px)`，只在 `transform` 上做动画（GPU 合成，不触发重排）
2. **朦胧光斑**：`mix-blend-mode: screen` 的圆形光晕，12–14s 呼吸式明暗变化
3. **半透明粒子**：Canvas 预渲染一枚柔光精灵，110 颗微粒缓慢上浮，正弦横向漂移

`src/components/Atmosphere.jsx` 是全局固定雾层，滚动时始终在内容之后，营造"站在光雾里"的连续感；各区块再叠加自己的局部雾带。

## 2. 材质：雾面玻璃

全站只有一种玻璃材质，定义在 `.glass`：

| 组成 | 取值 |
| --- | --- |
| 底色 | `rgba(222, 240, 249, .042)` |
| 模糊 | `backdrop-filter: blur(22px) saturate(1.12)` |
| 描边 | 1px 高光边（`--glass-line`）+ 内侧顶部一条亮线 |

导航、项目卡、优势卡、人物框共用这一套，改一处即全站生效。之所以把不透明度压到 0.042，是因为它常常叠在极光帘幕和等高线上——再亮一点就会把背景的绘图语言糊掉。

## 3. 首屏字体策略

首屏名字用 canvas 排版，依赖 web font。这里踩过两个坑，都已修掉：

1. **Google Fonts 的 `<link>` 会阻塞首屏渲染**。CDN 拉不到时浏览器一直等 stylesheet，React 根本没机会挂载——整页空白好几秒。现在改成 `media="print" onload="this.media='all'"` 异步加载，拉不到也不阻塞渲染。
2. **`document.fonts.ready` 要等所有字体（含中文分片）**，而 `<TechText />` 的入场动画原本挂在它上面：字体不到位 → 打字机不启动 → 只画得出虚线轮廓、实体字不显示。现在组件只等**自己用的那个字体**（`document.fonts.load`），且最多等 `FONT_WAIT_MS = 300ms`，之后先用回退字形开演，字体到位再 `refreshFonts` 重排一次。

Manrope 800 的拉丁子集（13.6KB）已自托管到 `public/fonts/manrope-latin-800.woff2`，首屏名字不再依赖任何外部请求；`index.html` 里对它做了 `preload`。打字机时长从 1.6s 收到 0.9s。

## 4. 极光背景层（`<Aurora />`）

`<Aurora />` 是 React Bits 的原生 WebGL shader（不依赖 three），色带在 OKLab 空间插值，所以色相过渡不会发灰。它挂在一个 `position: fixed` 的全屏层里，**从「个人经历」板块开始接管**，一路铺到页尾；首屏仍然只留骑行视频。

帘幕固定在视口顶部，所以它的浮现直接挂在滚动进度上：`<AuroraLayer />` 按「个人经历」板块顶边的高度算出 0→1 的进度，直接写进层的 `opacity`（不走 CSS 过渡、不触发 React 重渲染）。首屏的骑行视频退出视野时帘幕正好浮现完毕，不会出现整块切进来的硬跳。

参数是按"帘幕只占页面上沿、正文压得住"标定过的：

| 参数 | 取值 | 理由 |
| --- | --- | --- |
| `height` | 0.32 | 帘幕压到视口上沿三分之一，越往下越快淡出，正文区始终是暗底 |
| `opacity` | 0.85 | 帘幕收窄之后可以给足亮度，颜色才立得住；早期版本铺满全屏时只能给 0.09 |
| `brightness` | 1 | 同上 |
| `layers` | 2 | 第二层叠 0.32 的光，做出帘幕前后的层次 |
| `colorStops` | `#8fe3ff / #bdede1 / #6f9bff` | React Bits「北极」预设：青 → 薄荷 → 蓝紫，与站点雾青同系 |

CSS 上再压一层 `mask-image`，让帘幕集中在视口上三分之一、往下尽快淡出，免得长时间压住浅色卡片；`::after` 盖一层深色纱（顶部 0.1 → 底部 0.92），保证叠在帘幕上的浅色正文仍然读得清。

> **踩过的坑：WebGL 上下文不能提前销毁**
> `<Aurora />` 和 `<Topography />` 都在 effect 的 cleanup 里调过 `WEBGL_lose_context.loseContext()`。React 19 的 `StrictMode` 会 mount → cleanup → mount 再挂载一次，而同一个 canvas 只能有一个上下文：第一次的 cleanup 把上下文销毁后，第二次挂载拿到的是**已经死掉的上下文**，shader 编译直接失败，canvas 变成一块死白 / 死灰——表现就是"极光变成一片白雾"，看起来像强度调错了，其实是根本没画出来。
> 现在两个组件都改成：cleanup 只删 GL 资源、不销毁上下文；真正被浏览器收回上下文时走 `webglcontextlost` / `webglcontextrestored` 重建。

## 5. 测绘制图语言（`Survey`）

背景用的是 React Bits 的 `<Topography />`——发光等高线、每 5 条加粗的计曲线、十字测绘标记、海拔刻度、雾深与辉光。内容板块沿用同一套隐喻，把页面读成一张**地图**，四个板块是图上的四块图幅。

### 四个组件（`src/components/Survey/`）

| 组件 | 作用 | 对应背景里的 |
| --- | --- | --- |
| `<ContourRule />` | SVG 等高线分隔条 / 卡片内纹理。确定性随机（seed 决定地形，同 seed 永远同一张图）；线距按坡度收拢，一侧密一侧疏 | `lineCount` / `majorLines` / `detail` |
| `<Marker />` | 十字测绘标记，可闪烁 | `markers="plus"` |
| `<Ticks />` | 高程刻度尺，`level` 点亮前 N 格 | 刻度 / 比例尺 |
| `<Readout />` | 图幅规格读数条（TILE / SCALE / CONTOUR / GRID / DATUM） | HUD 数据层 |

### 落到每个板块

- **板块头**：统一用 `<SectionHead />`——编号 + 标题 + 图幅读数 + 说明 + 一条横贯版心的等高线断口
- **个人经历**：时间线改成**剖面轴**（一条带刻度的测量杆 + 十字站点）；统计卡带高程刻度尺，刻度点亮格数 = 实际数量；人物图下挂图幅坐标条
- **精选项目**：详情面板头下压一条等高线；职责项用十字标记；「核心链路」由一排圆角 chip 改成**测量杆式阶梯**；卡面叠一层极淡等高线纹理
- **个人优势**：卡片上半部压一片等高线地形（向下淡出，不压正文）；hover 时指针附近那圈等高线被点亮——与背景 `hoverEffect="trace"` 同构
- **整屏联系**：标题与联系方式之间一条横贯全幅的等高线带；渠道项带十字标记

### 两条硬约束

1. **等高线必须保持 1px 物理宽度**。SVG 用 `preserveAspectRatio="none"` 拉伸，`vector-effect: non-scaling-stroke` **必须挂在每个 `<path>` 上**——它不是继承属性，挂在 `<g>` 上不生效，会被拉成粗横带。
2. **纹理不与正文抢读**。卡片内等高线用 `mask-image` 向下淡出，或整体压到 0.3 以下不透明度。

### 改图幅参数

`src/data/profile.js` 里的 `survey` 导出控制四个板块右上角的读数条（`TILE` / `SCALE` / `CONTOUR` / `GRID` / `DATUM`），改这一个对象即可。

## 6. 星盘统计格（`<StarBorder />`）

「个人经历」的四格数据（0→1 / 4 / 3 / 12+）用 React Bits 的 `<StarBorder />` 重做：一颗星头沿圆角边框巡游，身后拖着衰减的辉光，格子随指针点亮。

### 参数选择

| 参数 | 取值 | 理由 |
| --- | --- | --- |
| `color` | `#D8F2F8` | 星头偏白青，是全站最亮的一档 |
| `trailColor` | `#4E93AB` | 拖尾落回背景地形同款蓝，两层动效接得上 |
| `duration` | 6 / 6.5 / 7 / 7.5 | 四格错开节拍，避免四个动画同步显得机械 |
| `radius` | 10 | 圆角比其他卡片略大，读作独立面板 |
| `glow` | 0.55 | 四格同时发光，再高会糊成一片 |
| `hover` | `lap` | 悬停时星头额外绕行一圈 |
| `backgroundColor` | `transparent` | 保住玻璃拟态，组件默认的不透明底色会盖掉雾层 |
| `borderColor` | `rgba(220,238,248,.18)` | 静止态描边，对齐 `--line-2` |

### 三条坑

1. **`.star-border` 是全局类，`.stat` 是 CSS Module 类**——两者特异性相同，谁生效取决于 CSS 注入顺序。改样式一律写成 `.stats .stat`（特异性 0,2,0）压住它，不要赌顺序。
2. **组件默认是按钮排版**（`inline-flex` + 居中 + `padding: .875rem 1.5rem` + `font-weight: 500`）。数据面板要竖排、左对齐、`font-weight: 400`，这些都必须在 `.stats .stat` 里显式覆盖。
3. **辉光画布会溢出 48px**（`BLEED = 48`，画布定位在 `-48px`、尺寸 `calc(100% + 96px)`）。这是有意的出血效果，和 Hero 视频、雾带同一写法；`body` 的 `overflow-x: hidden` 会裁掉，所以**页面不会真的横向滚动**——自检脚本判据因此改成"能否横向滚动"，而不是 `scrollWidth > clientWidth`。

`prefers-reduced-motion` 下组件自停：星头不再巡游，只留一个静态光点，星光粒子也不发射。

## 7. 工具星座（`NeuronGlobe`）

「个人经历」末尾的工具链不是标签云，而是一个**大球体**：25 个工具是球面上的枢纽星点，按能力簇分 5 色，周围密织的星与连线构成星群。

> React Bits Pro 的 `<Astral Shell />` 是付费组件（需 `REACTBITS_LICENSE_KEY` + components.json 注册表 + Tailwind），本项目三者都没有。文档页公开了完整参数表，因此按规格自研了等价实现，视觉与交互对齐：慢速自转、聚簇连线、深度衰减、指针点亮、拖拽带惯性、点击沿球面扩散的脉冲。

### 单球与鼠标控速

原来的设计是「每个能力簇一个球体，五个球各转各的」——多球的代价是版面被切成五块、视线要来回跳。现在合并成**一个球体**，25 个工具都在球面上，按能力簇分色：

| | 取值 | 说明 |
| --- | --- | --- |
| `groupBy` | `'all'` | 所有工具进同一个球；`'group'` 仍可按能力簇分球 |

球固定在版面中央，**鼠标拖动直接施加旋转角速度**，四个方向都能控制：

| 拖动方向 | 作用 | 实现 |
| --- | --- | --- |
| 左右 | 加快 / 反转绕 Y 轴的自转 | `angle += dx × 0.006`，同时记成角速度 `velY` |
| 上下 | 拧动绕 X 轴的俯仰（限 ±68°，松手回正） | `tilt += -dy × 0.05`，记成角速度 `velX` |

拖得越快转得越快；松手后角速度按 `exp(-dt/0.7)` 衰减，球回到 60 秒一圈的基础自转节拍，俯仰也慢慢回正到初始倾角。

单球的好处是标签只需绕一圈：`relaxAngles` 按文字宽度算最小间距就能把 25 个名字排开，展开态不会互相压字。

### 三种标注状态

| 状态 | 表现 |
| --- | --- |
| 常态 | 名字贴着星点，只在正面且不压字时才显示 |
| 悬停某个枢纽 | 该星点拉出一条**引线**，名字落在引线末端；整簇连线一并点亮 |
| 拖动球体 | 球体不位移，鼠标直接施加旋转角速度：左右控自转快慢，上下拧俯仰；松手惯性衰减 |
| 点击球体 | 球上的工具名**全部展开**，每个名字带一条引线连回球体（神经元式）；再点一次收起，点球外也收起 |

展开时球体缩 12% 给外圈让位；标签沿圆周做**角度松弛**（按文字宽度算最小间距），且角度**平滑跟随**——直接每帧重排会让标签随球体自转抖动。

### 参数选择

| 参数 | 取值 | 理由 |
| --- | --- | --- |
| `nodesPerSphere` | 240 | 球面上的星点数 |
| `reach` | 0.28 | 3D 弦长阈值。N=240 时最近邻弦长约 0.23，0.28 刚好连出 4~5 条 |
| `clustering` | 0.16 | 背景星点向最近枢纽靠拢的比例。**调大就会塌缩成扇形，球面轮廓消失** |
| `connections` | 3 | 每颗星连最近 3 个邻居 |
| `depthFade` | 0.55 | 背面只压到 45%：要看得见背面的网，球才成球 |
| `spin` | 1 | 60 秒转一圈，比站点的雾层还慢 |

### 单球的算术

球半径是**反解**出来的：

```
R = min( (版心宽 - 2×(环半径 44 + 文字宽 78) - (n-1)×间距 26) / (2n), 画布高 × 0.36 )
```

单球（n=1）时宽度允许到 600px 以上，但画布只有 446px 高、半径不能超过高度的 36%，所以实际 R ≈ 160px。反过来 n=5 时宽度先卡住，每个球只能分到约 126px——这正是合并成单球的理由，省下的横向空间全部让给了高度。

### 五条坑

1. **枢纽必须长在球面上**。最初把工具单独用一套斐波那契球摆点，再让背景星点聚过去——结果 `clustering=0.9` 时背景全塌成 25 个小碎块，球没了。正确做法：所有星点先均匀铺球，工具从这批星点里**均匀挑出**，其余星点只轻微靠拢。
2. **canvas 的 `shadowBlur` 是头号掉帧源**。标签文字每帧每条都要单独做一次模糊光栅化。改用四向偏移描边当暗色光晕，成本几乎为零，效果一样。
3. **别在 `draw` 内部再排下一帧**。`loop` 自续 + `draw` 里又 `requestAnimationFrame(draw)`，回调数每帧翻倍、指数增长——实测 4fps。修掉后 180fps。
4. **`net.owner` 存的是枢纽下标，不是背景星点下标**。曾用 `net.owner.findIndex(o => o === hub)` 去取"第一个属于该枢纽的背景星点下标"，再拿它跟 `owner` 比较——维度不对，"整簇点亮"其实只在小下标时偶然生效。现在直接用枢纽下标比较。
5. **一次改一个文件**。分两次写同一个文件时，Vite 的 watcher 会把两次事件合并，读到的是中间态——线上表现为 `onExpandRef is not defined`，而源码里明明有。

另外：连线不要逐条 `stroke()`（几千条就是几千次独立光栅化），按 alpha 分桶批量描边；背景星点同理，分桶 `arc` + `fill`，只给最亮的一批叠辉光精灵。

### 降级动效

`prefers-reduced-motion` 下：停止自转、冻结星光闪烁、点击脉冲仍可用（用户主动操作）。自检脚本比对球体画布两帧的 `toDataURL()`，确认逐像素静止。

## 8. 弧形联系条（`<CurvedInput />`）

联系页原本是一行大字邮箱，现在换成一条**弧形输入条**承载 GitHub 账号：左端是 GitHub 标记芯片，中间是沿弧线排的文字 `github.com/lisu0429`，右端是「前往」按钮。

组件来自 React Bits（`src/components/CurvedInput/`），文字是真的排在一段圆弧上的（`<textPath>`），不是普通输入框贴个弧形背景。

### 参数选择

| 参数 | 取值 | 理由 |
| --- | --- | --- |
| `bend` | 30 | 弧高。过小看不出是"弯"的，过大文字会挤 |
| `height` | 76 | 与原大字邮箱同一量级 |
| `fontSize` | 25 | 弧上文字 |
| `cornerRadius` | 20 | 条与按钮的圆角 |
| `borderColor` | `rgba(169,222,232,.3)` | 对齐全站的雾青描边 |
| `buttonColor` / `buttonTextColor` | `#A9DEE8` / `#06131B` | 雾青底 + 墨色字，避开组件自带的紫色主题 |

### 三点注意

1. **组件的默认配色是紫的**（`#A855F7`），必须逐个颜色 prop 覆盖，否则和全站的雾青体系打架。
2. **`icon` 传自定义节点会顶掉默认的信封芯片**（含芯片底板）。想保留芯片质感就得自己把圆角矩形画进去。
3. **要把它当只读展示用**，就得传受控 `value` + 一个空 `onChange`；否则用户能真的把网址改掉。传 `value` 但不传 `onChange` 会触发 React 警告。

点击「前往」或按回车都会 `onSubmit` → 新标签打开 GitHub 主页；邮箱与电话仍在底部的渠道行里。

## 9. 动效编排（GSAP + ScrollTrigger）

动效全部收在 `src/motion/`，组件只负责声明角色（`data-anim` / `data-scene`），不写动画代码。

| 文件 | 职责 |
| --- | --- |
| `gsapCore.js` | 注册插件、缓动词汇表（`EASE`）、时长档（`DUR`）、降级判断 |
| `heroIntro.js` | 首屏 opening：一条 3.2s 的编排时间线 |
| `scrollChoreography.js` | 各板块滚动进场 + 媒体视差 |
| `index.js` | 总入口，用 `gsap.context()` 统一作用域，卸载时一次 revert |

### 首屏 opening 的顺序

`媒体幕布揭开 → 导航落下 → 小标签升起 → 巨名遮罩掀开 + 压缩后归位 → 副文案擦入 → CTA 依次落位 → 底部信息条逐条升起`

巨名那一段是重点：`yPercent 16 → 0` 位移、`scaleY 0.74 → 1` 纵向压缩后归位、`scaleX 1.05 → 1` 横向回弹，再叠一道 `clip-path` 自上而下的幕布。揭完就把 `clip-path` 摘掉，否则那圈 `drop-shadow` 光晕会被裁掉。

### 滚动编排

每个板块（`data-scene`）头部是一条整体时间线，内容块各自带触发点，滚到才进：

`英文标签横向擦入 → 大标题自遮罩后升起（领先内容 0.3s）→ 说明读数 → 等高线分隔线自左展开 → 卡片 / 列表行依次 stagger`

标题的"自遮罩后升起"靠 `.sec-titleMask`（`overflow: hidden`）裁切，不是 `clip-path`——`clip-path` 会把标题自己的 `text-shadow` 一起裁掉。

### 三条硬约束

1. **只用 `transform` / `opacity` / `clip-path`**，不碰会触发重排的属性（宽高、top、margin）。
2. **不用 `back` / `elastic`**：任何回弹都会把"高级"变成"廉价"，全部走 `power4.out`。
3. **入场用 `once: true`、视差用 `scrub`**，每个元素只跑一次入场；`will-change` 只在遮罩揭开期间挂上，动画结束立刻撤。

### 降级

`prefers-reduced-motion: reduce` 时直接 `clearProps` 全部动效属性，内容一上来就是终态；`src/styles/base.css` 里不再有 `[data-reveal]` 那种"先藏起来"的规则——GSAP 挂了也只是内容直接可见，不会永远空白。

> 踩过的坑：**GSAP 3.15 起 `ScrollTrigger.context()` 已被移除**，统一用核心的 `gsap.context()`；在它里面创建的 ScrollTrigger 会自动纳入作用域。

## 10. 交互与响应式

### 交互规约

- Hover：前景元素提亮（边框转雾青、文字发光、玻璃层变亮），**不加快烟雾**
- Active：`translateY(1px)` 轻微下沉
- 所有雾的漂移周期落在 9–14s，粒子速度 0.05–0.27px/帧，无快速闪动
- 项目区 CardSwap：7s 自动轮播，鼠标悬停右侧详情面板即暂停，卡片可拖拽甩出，编号圆点可跳转
- 统一动效曲线 `--ease: cubic-bezier(.16,1,.3,1)`

### 版心与断点

版心宽度 `--shell: 1700px`（`src/styles/tokens.css`），断点以 1280px / 1100px 为主，主要面向 PC 端展示。移动端目前没有做专项适配——这是刻意的取舍：四个板块都是横向多栏布局，硬压到 375px 宽会牺牲信息密度。
